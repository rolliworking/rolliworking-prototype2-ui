**One paragraph.** The station opens from **any reference** — a job label, a `REF-SERIAL` label, an SO number (digits), an estimate number (→ picker when several orders) or the pickup QR itself (`RSPU:<SO#>:<code>`, whose code is carried to step 3). Gate 2 is now **invoice Sent + QBO balance read at the gate**: a never-sent invoice blocks, a QBO mismatch blocks until re-read or paid, a zero-balance order is `excluded`; the only way past a balance is still a bypass approved by a *different* manager with a reason. Codes are **six digits**; three wrong codes lock code / QR entry for **ten minutes** (proxy + reverse QR stay open). When Σ item value + invoice total is **≥ $10 000**, the primary identity is not enough: the client confirms on the counter's **paired kiosk** — a one-time code pushed by SMS or a client-operated ID photo — unless the identity was already a reverse QR on the client's phone (the fallback). **Authorized pickup persons** live on the client record and release *without* manager approval (government-ID photo still required and logged "authorized"); anyone else is a proxy. Every camera-evidenced release stamps a **Reolink clip reference** (counter channel, hand-over window, 90-day retention). Every **ID photo is `identity` class**: manager-tier only, stripped in the data layer for everyone else, never on the portal or in an export, purged with the warranty window while the fact "ID · purged" stays.

## Release re-validation (`pickupBlockers`, re-run by `confirmPickup`)
Order of blockers as built: **−1 client asset** (any component of the job without a real custody event — `specs/SPEC-CUSTODY-AUDIT.md`, hard stop until backfilled) → item not confirmed → invoice not sent → QBO not read → QBO mismatch → balance due → identity not verified → proxy without approval or authorized id → **value tier without second factor** → hand-back photo / serial check → first frame or camera bypass. The UI mirrors this list; it never decides.
