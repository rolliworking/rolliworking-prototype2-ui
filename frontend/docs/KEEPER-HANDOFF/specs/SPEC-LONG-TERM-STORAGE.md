# SPEC — LONG-TERM STORAGE (LTS) — **PLANNED** (not built; full spec text arrives when the build starts)

**Status: PLANNED** — filed 2026-10-02 from MH's queue summary. Nothing in `/app/frontend/src` implements it yet; no route, no type, no export. When MH pastes the full text this file becomes the build brief and the docs delta (route map, data model, audit family, UI conventions) is written in the same pass.

**One paragraph.** Long-term storage is the answer to a finished (or parked) watch that nobody is collecting: once a job has sat ready / unpaid / unclaimed past a **Setup threshold** (days, manager-editable), it appears on **MH's Hitlist card** ("Long-term storage · n pieces · oldest N d") and can be moved — **by scan only**, never by a click on a board — into a new **LTS safe container node** on the Assign / Move and Shop Floor maps (a locked safe node like the manager safes, owner shown, container custody like the JV bin: the safe holds custody, the ticket's location follows the safe). The move stamps a new job status **`in_storage`** ("In storage") with a chip on every job row (jobs list, All jobs, Client 360, Hitlist, Concierge, search hits) and on the W·B·P dot row (dots stay blue/finished; the chip says *stored*), and queues a **client notice** (Sent-record, portal-first, template `long_term_storage`) telling the client where the piece is and how to collect or ship it. Leaving storage is again scan-only (LTS safe → Pickup Station or Ship Station queue) and clears the status; every entry / exit is an append-only custody move (`via: 'lts'`) plus an audit row. Expected pieces: `JobStatus 'in_storage'` (JOB_FLOW tail, skipped by every kind unless entered by scan), `RwStationKey 'lts_safe'` (container node, auditable in the stage/bin audit), `Setup → Storage` threshold (`setLtsThresholdDays`, default TBD by MH), Hitlist derived row for MH + a per-piece row for the account manager, `TemplateKey 'long_term_storage'`, Client 360 custody row "Moved to long-term storage", and reports filter `in_storage`. Open for MH with the paste: threshold default and whether it counts from `finishedAt` or from the last client contact; storage fee line on the SO (yes / no); who may scan OUT (manager only vs any concierge+); whether LTS pieces count in the asset-value tile on MH Accountability (today every job in custody counts).
