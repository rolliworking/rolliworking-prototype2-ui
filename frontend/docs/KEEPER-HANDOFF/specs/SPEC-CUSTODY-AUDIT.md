**One paragraph.** Legacy (Lovable) custody is not trusted. Real custody is a ledger of **physical scans at a node** — `audit` (during an audit session), `backfill` (the one-tap fix) and `scan` (every ordinary station / pad / bulk / gate move). An open-job item with no real event is **not on hand**: it renders as **"−1 client asset"** wherever a location would be shown and the totals count it as −1; the seeded position is only a grey "last seen (legacy)" hint. An **audit session** walks a scope (whole shop · station group · safe) node by node — scan the node, optionally a bin, then the items; unknown labels become stubs; closing the audit turns every expected-but-unscanned item into **UNACCOUNTED**. The fix is always the same: stand at the node, scan the item, say why → `backfill`. Keeper starts EMPTY; the first physical audit builds custody.

## Model (`api/custody.ts`)
- `CustodyEvent { id, itemKey (jobId:part | bin:BIN-xx | stub:id), jobId?, jobNumber?, part?, toNode, nodeLabel, binLabel?, source: audit | backfill | scan, by, station, at, why?, auditId? }` — append-only.
- `CustodyAudit { id, by, station, startedAt, status: open | paused | closed, scope { kind: shop | station | safe, key?, label }, nodeKeys[], nodes: Record<node, { status open | closed, scanned[], closedAt?, by? }>, currentNode?, currentBin?, stubIds[], result?: { unaccounted[], foundNoJob[] } }`.
- `ItemStub { id, label, reference?, serial?, node, nodeLabel, at, by, auditId, reviewed? }` — "found, no job".
- `CustodyCurrent { onHand, event?, legacy?: { label, at? } }` (`custodyCurrentSync(job, component)`), `UnaccountedRow`, `CustodyProgress` (nodes closed, items scanned, expected / found / unaccounted, per node), `CoverageReport { total, covered, pct, byNode[], trend[], since }`.
- Scopes: `SCOPE_STATIONS` wm_room (WM benches + testing) · band_room (band assign, refinish, polish room, band QC, JV bench) · front_desk (finished, pre-approval, FD safe); safes resolve their trays through `registerSafeFor` (`api/safes.ts` parents).

## Rules
1. **No scan, no custody (D-509).** `custodyCurrentSync` = last ledger event for the item or `onHand: false` + legacy hint. `onPartMoved` hook writes a `scan` event for every ordinary move, so the audit only has to catch what the shop never scanned.
2. **−1 everywhere (D-510).** `minusOneSync(jobId)` feeds `CustodyChip` (`custody-chip-<job>-<part>[data-state]`) on the job custody card (`job-custody-card[data-minus]`), the SO strip, the pickup / ship gates (a −1 part blocks release until fixed), `/custody`, Analytics (`safes-minus1-count|value`) and the Unaccounted list (`custody-unaccounted-list[data-count]`, `custody-minus1-<job>-<part>`).
3. **Audit session (D-511).** `startCustodyAudit(kind, key)` → `custodyAuditScan(id, code)`: station label / key → picks the node (outside-scope nodes refused, shelf bins allowed anywhere) · `BIN-xx` / `BIN-JV` → bin at the node (next items ride in it) · item label (`E0####`, `E0####|B`, `BAND-E0####`, full serial) → `audit` event + the part moves there (`via: custody_audit`) · unknown → `{ kind: 'unknown' }` → `custodyAuditStub(label, ref, serial)`. `closeAuditNode`, `pauseCustodyAudit` / `resumeCustodyAudit` (scans refused while paused), `closeCustodyAudit` → `result.unaccounted` = in-scope items never scanned and without real custody anywhere; `foundNoJob` = stubs. Every start / close / stub writes a `job` audit row.
4. **Backfill = the one-tap fix (D-512).** `backfillCustody(jobId, part, node, scannedLabel, why)`: the scanned label must resolve to THAT job ("That label is not E02017 — scan the item itself"), the node must exist, a reason is required → `backfill` event (+ move `via: custody_backfill`) + audit row "Custody BACKFILL · …". UI: `custody-chip-<job>-<part>-fix` → `custody-backfill-node` · `custody-backfill-scan` · `custody-backfill-confirm`.
5. **Invoice flag + pins (D-513).** `sendInvoice` records `custodyAtInvoice: 'minus_one'` on the send (`so-invoice-send-custody-<n>`) and upserts a VC hitlist item "−1 at invoice" (`custody-minus1-invoice:<so>`) resolved on backfill; `syncPins` keeps MH's standing "Custody coverage n % · k client assets not on hand" item (`custody-coverage`, link `/setup/custody`) until coverage is 100 %. Both run in the day sweep so `/today` sees them.
6. **Reports.** `coverageSync()` (per node + daily trend since the first audit) on `/setup/custody` (`custody-coverage-pct[data-pct]`) and Analytics; `auditLogCsv()` = every non-scan event; `getCustodyEventsSync(filter)` for job pages.
7. **Persistence**: in-memory ledger, seeded lazily on first custody read (`seedCustody`). Keeper (naming per KEEPER D-432): **`custody_events`** is the record — one row per physical scan `{ event_id, item_key, job_id, part, to_node, bin_label, source: scan | audit | backfill, by, station, at, why, audit_id }`, append-only; the move trigger writes `source = scan` rows. The audit **session is only the wrapper** around its events: `custody_audits` (scope, status, nodes, result) + `custody_audit_nodes`; `item_stubs` for "found, no job". Current custody and coverage are views over `custody_events`, never stored.
